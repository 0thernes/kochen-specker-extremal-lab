Kochen-Specker Extremal Lab

How few rays can a Kochen-Specker set have, if the rays must come from a given finite pool?

This lab computes that number exactly for several pools and certifies the answers. The general question, with any rays allowed, stays open: nothing here settles it.

What a Kochen-Specker set is

Take a finite set of directions in space (rays: lines through the origin) and try to label each one 1 or 0 so that two perpendicular rays are never both 1, and every three mutually perpendicular rays in the set include a 1. A Kochen-Specker (KS) set is a set of rays for which no such labelling exists. Kochen and Specker showed in 1967 that such sets exist; in quantum theory this means that the answers to yes/no measurements along the rays cannot all be fixed in advance, independently of which perpendicular rays each one is measured together with.

Terms used below: a basis is a set of d mutually perpendicular rays in dimension d (three rays in ordinary space). Rule 1: two perpendicular rays are never both 1. Rule 2: every basis inside the set contains a 1. A set with a labelling that obeys both rules is called colourable.

The open problem

How small can a KS set be? In three dimensions nobody knows. The smallest one known has 31 rays (Conway and Kochen), and it has been proved that at least 24 rays are needed. Whether the true minimum is 24, 31 or something in between is an open problem.

What this lab did, and what it did not do

It did not

  • find a KS set smaller than any published one, in any dimension;
  • solve the open problem above, or narrow the range 24 to 31;
  • say anything about rays outside the pools it examined.

It did

  • fix a finite pool of candidate rays, for example the 49 directions whose coordinates are whole numbers between −2 and 2;
  • determine the exact size of the smallest KS set that uses only rays from that pool (for those 49 rays: 31);
  • certify the answers: two of them are theorems checked by the Lean 4 proof assistant, and several have certificates that independent programs re-check, including this page.

Results

Each row is one pool. “Minimum KS set” is the smallest number of pool rays that form a KS set. The status words say how strongly each number is established; rows marked provisional are not final. The register of record is results/RESULTS.md in the repository. Several of these values were reported before by others without proof (31 for whole-number coordinates up to 2, 3 and 4; 33 for sixth roots of unity; 29 as the smallest set generated from the coordinates 0, +1, −1 in dimension five); what is new here is mainly the proof that nothing smaller exists, in a form that can be re-checked. The paper, Section 1.3, gives the credits.

      Verify in your browser

      The buttons below run the real checks, here, on your device, using the data files this page loaded: exact integer arithmetic and exhaustive search in plain JavaScript, with no SAT solver and no server. The code (assets/verify.js) is a port of the repository’s independent verifier. A PASS depends on that code and on your browser being correct; the Lean theorems in the repository are the authoritative statements.

      Data files

      Before anything is checked, the page computes the SHA-256 of every data file and compares it with data/manifest.json. A file that differs is reported here, and every check that uses it reports FAIL. This catches a damaged or swapped file; it cannot catch someone who replaces a file and the manifest together, so the hashes of the certificate files are also printed in verify/README.md in the repository.

      Hashing the data files…

      (a) The 49-ray pool: recompute orthogonality and the bases

      Recomputes every dot product from the integer coordinates, compares the result with the file’s table of perpendicular pairs, enumerates all triples of mutually perpendicular rays and compares them with the file’s list of bases.

      (b) The 49-ray pool: replay the certificate tree

      Replays the search-tree certificate node by node. If every node is accepted, every set of at most 30 rays of the pool is colourable, so no KS set that small exists in the pool.

      (c) The 31-ray set: search for a colouring

      Tries, by exhaustive backtracking, to label the 31 rays so that both rules hold, then repeats the search in a different order as a cross-check, and confirms that all 31 rays belong to the 49-ray pool.

      (d) Four dimensions, the 40-ray pool: recompute the pool and replay the certificate

      The same two steps as (a) and (b) for the pool of all rays in four dimensions with entries 0, +1, −1: orthogonality and bases are recomputed, then the certificate that every set of at most 17 rays is colourable is replayed.

      (d) Four dimensions, the 18-ray set: search for a colouring

      The same search as (c) for an 18-ray set inside the 40-ray pool.

      How to reproduce

      Clone the repository; then, from its top folder (Node 22 or newer and Lean 4):

      # the independent verifier on the two certificates checked on this page
node verify/verify_cert.mjs results/cert_box3_H2_k30.json results/cert_box4_H1_k17.json

# the 31-ray set is a KS set, and no ray can be removed
node verify/verify_cert.mjs --ks results/ks31_box3_H2.json --require-critical

# the verifier's own tests, including corrupted certificates that must be rejected
node verify/test_verify.mjs

# this page's port of the verifier, compared with the original
node docs/assets/verify.test.mjs

# the Lean theorems (checked by the Lean kernel)
cd lean
lake build
